## Summary:

I moved the application from local VMs to AWS. Terraform creates the network, an EKS cluster and an RDS PostgreSQL database. The application runs in EKS from the same Docker Hub image that Jenkins builds, the data was moved to RDS from the database dump.

On Kubernetes I added probes, resource requests and limits, an HPA and the Pod Security Standards restricted profile. Application secrets are now generated by Terraform, stored in AWS Secrets Manager and synced into the cluster by External Secrets Operator. For observability I installed kube-prometheus-stack (Prometheus and Grafana) and Loki with Alloy for logs.

All cloud work is on one branch, feature/iac-aws. The stack is destroyed after every work session to save money.

## Goals:

- Main goal: the application runs in AWS, the infrastructure is described as code;
- Other goals: secure pods, secrets out of git and out of manual steps, metrics and logs in Grafana.

## Results:

- What I did: Terraform code for AWS, Kubernetes manifests for the app, Pod Security, External Secrets, Helm values for monitoring and logging;
- What I achieved: the whole stack can be created from zero and destroyed with a few commands, no secret is created by hand, metrics and logs of the cluster and the app are in Grafana.

Infrastructure as Code and migration. Terraform uses the community modules for VPC and EKS. I chose Kubernetes 1.36 because versions 1.33 and lower are on extended support, which costs 6 times more ($0.60 per hour instead of $0.10). There is no NAT Gateway: nodes are in public subnets, RDS is in private subnets and open only for the nodes. The data was loaded into RDS from the dump with a temporary postgres pod.

Orchestration. Two replicas, HPA scales from 2 to 4 pods at 70% CPU. The app container has a TCP probe on port 8000, nginx has an HTTP probe on /healthz.

Pod Security. The pyforum namespace has the label pod-security.kubernetes.io/enforce: restricted. All containers run as non-root with a fixed UID, seccomp RuntimeDefault, no privilege escalation and all capabilities dropped. A test pod with default nginx settings is rejected by the API server.

Secret management. Terraform generates the DB password and SECRET_KEY with random_password and saves them to Secrets Manager. External Secrets Operator gets access through EKS Pod Identity, the IAM role can read only this one secret. ExternalSecret creates the Kubernetes Secret pyforum-secret and refreshes it every hour.

Monitoring. kube-prometheus-stack in the monitoring namespace: Prometheus, Grafana, node-exporter on every node, kube-state-metrics. Alertmanager and the control plane targets (scheduler, controller manager, etcd, kube-proxy) are switched off: EKS manages the control plane and these endpoints are not reachable. Metrics are kept for 1 day.

Logging. Loki runs in single binary mode with storage in the pod volume, logs are kept for 24 hours. Alloy reads the logs of all pods through the Kubernetes API and sends them to Loki with the labels namespace, pod and container. Loki is added to Grafana as a data source in the Helm values. In the logs I found requests to the load balancer by its IP address: Django rejects them with DisallowedHost, because only the LB name is in ALLOWED_HOSTS.

## Problems and Solutions:

| #   | Problem | Solution | Status |
| --- | ------- | -------- | ------ |
| 1   | EKS 1.33 and lower are on extended support, 6 times more expensive | Kubernetes 1.36 | Done |
| 2   | Media files are not served: Django serves media only with DEBUG=True | Init container copies media from the image to a shared volume, nginx sidecar serves /media/ and proxies the rest to the app | Done |
| 3   | HTTP probe to Django returns 400: the pod IP is not in ALLOWED_HOSTS | TCP probe on the app container, HTTP probe on /healthz in nginx | Done |
| 4   | runAsNonRoot does not work with a user set by name in the image | runAsUser 999 set in the securityContext | Done |
| 5   | Default nginx image needs root for port 80 | nginx-unprivileged on port 8080, Service targetPort 8080 | Done |
| 6   | The app Secret was created by hand with kubectl | Secret generated by Terraform, synced by External Secrets | Done |
| 7   | The generated password is saved in the Terraform state | State is in an encrypted S3 bucket; for production a write-only attribute is better | Known limitation |
| 8   | The load balancer name changes after every recreate, ALLOWED_HOSTS has to be updated | Updated in the ConfigMap after apply; a domain with Ingress is a next step | Known limitation |
| 9   | terraform destroy can not delete the VPC while the LB created by Kubernetes exists | Delete the Service first, then terraform destroy | Done |
| 10  | The temporary pod for the DB dump is rejected in the restricted namespace | The pod runs in the default namespace | Done |
| 11  | Default Loki chart is made for a big cluster (3 replicas of each part, caches, persistent disks) | Single binary mode, caches and gateway switched off, emptyDir storage | Done |
